# Exemples de réponses selon le mode de commentaire

Ce document montre comment l'IA devrait formater ses réponses selon le mode configuré.

## Mode `global` (défaut)

L'IA génère une review complète en markdown :

```markdown
# Code Review

## 1. Summary of changes
- Added authentication middleware to protect API routes
- Implemented JWT token validation
- Added user role-based access control

## 2. Code Clarity
The code is generally well-structured. Variable names are descriptive and the flow is easy to follow.

## 3. Naming and Comments
Good use of descriptive function names. Consider adding JSDoc comments to exported functions.

## 4. Code Simplification
The authentication logic could be extracted into a separate service class for better reusability.

Example:
\`\`\`typescript
class AuthService {
  validateToken(token: string): boolean { ... }
  checkPermissions(user: User, resource: string): boolean { ... }
}
\`\`\`

## 5. Bugs
- **Line 42 in src/auth/middleware.ts**: Missing null check before accessing `user.role`
- **Line 89 in src/api/routes.ts**: Race condition possible if token expires during request

## 6. Security Issues
- **Line 23 in src/auth/login.ts**: Password is logged in plain text (line `console.log(password)`)
- Consider using bcrypt for password hashing
- JWT secret should be at least 256 bits

---
*This comment was generated by an artificial intelligence duck.*
```

## Mode `inline`

L'IA génère uniquement des commentaires avec le format spécial pour être parsés :

```
In `src/auth/middleware.ts` line 42: Missing null check before accessing `user.role`. This could throw a TypeError if user is undefined.

In `src/api/routes.ts` line 89: Race condition possible if token expires during request. Consider refreshing the token validity at the start of each handler.

In `src/auth/login.ts` line 23: Security issue - password is logged in plain text. Remove the console.log statement immediately.

In `src/auth/token.ts` line 56: Consider using a constant for the token expiration time instead of hardcoding 3600.

In `src/models/user.ts` line 15: The type definition could be more specific. Use `'admin' | 'user' | 'guest'` instead of `string` for the role field.
```

**Résultat dans GitLab :**
- 5 commentaires inline directement sur les lignes concernées
- Aucun commentaire global

## Mode `hybrid`

L'IA génère à la fois un résumé ET des commentaires inline :

```markdown

## Overall Assessment
Good implementation of authentication with JWT. The code is generally well-structured, but there are a few security concerns and potential bugs that need attention.

## Key Strengths
- Clean separation of concerns
- Good error handling in most places
- Comprehensive test coverage

## Areas for Improvement
- Security: Password logging issue
- Robustness: Missing null checks
- Configuration: Hardcoded values

---

## Specific Issues

In `src/auth/middleware.ts` line 42: Missing null check before accessing `user.role`. This could throw a TypeError if user is undefined.

In `src/api/routes.ts` line 89: Race condition possible if token expires during request. Consider refreshing the token validity at the start of each handler.

In `src/auth/login.ts` line 23: Security issue - password is logged in plain text. Remove the console.log statement immediately.

In `src/auth/token.ts` line 56: Consider using a constant for the token expiration time instead of hardcoding 3600.

---

## Recommendations
1. Add integration tests for the complete auth flow
2. Document the JWT token structure
3. Consider rate limiting on login endpoint

---
*This comment was generated by an artificial intelligence duck.*
```

**Résultat dans GitLab :**
- 1 commentaire global avec le résumé et les recommandations
- 4 commentaires inline sur les lignes spécifiques

## Notes pour les développeurs

### Patterns de parsing (modes `inline` et `hybrid`)

Le système détecte automatiquement ces patterns :

```regex
// Pattern 1: Standard
In `src/file.ts` line 42: Your comment here

// Pattern 2: Compact
src/file.ts:42: Your comment here

// Pattern 3: Markdown list
- `src/file.ts:42` - Your comment here
```

### Format JSON (mode `structured`)

Le JSON peut être enveloppé dans un bloc markdown :

````
```json
{
  "summary": "...",
  "inline_comments": [...]
}
```
````

Ou être fourni directement :

```json
{
  "summary": "...",
  "inline_comments": [...]
}
```

Le système essaie d'extraire le JSON et fallback sur le parsing de patterns si le JSON est invalide.

## Conseils pour améliorer la qualité des reviews

### Pour le mode `inline`
- Demandez à l'IA d'être **spécifique** et de toujours mentionner le fichier et la ligne
- Évitez les observations générales qui ne peuvent pas être liées à une ligne

### Pour le mode `hybrid`
- Séparez clairement le **résumé général** des **problèmes spécifiques**
- Le résumé doit contenir les observations globales et recommandations
- Les détails spécifiques doivent utiliser le format inline

### Pour le mode `structured`
- Testez d'abord avec des MR simples pour valider le format JSON
- Vérifiez que l'IA génère un JSON valide (pas de trailing commas, quotes correctes)
- Le `summary` peut contenir du markdown complet

---

## Debugging

### Les commentaires inline n'apparaissent pas

1. Vérifiez que le mode est bien configuré dans `.env`
2. Consultez les logs pour voir les SHAs de commits
3. Vérifiez que l'IA génère bien les patterns attendus
4. Testez avec un exemple simple d'abord

### L'IA ne génère pas le bon format

Ajustez le prompt dans `src/prompt/index.ts` pour être plus explicite :

```typescript
const INLINE_INSTRUCTIONS = `
IMPORTANT: For every specific issue you find, use this EXACT format:
In \`path/to/file.ts\` line 123: Your comment here

Example:
In \`src/api/routes.ts\` line 42: Missing error handling

Do NOT use any other format for inline comments.
`
```
